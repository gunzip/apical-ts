Generated `routes/`, `client/`, and `server/` outputs now use the Standard
Schema validation contract instead of exposing Zod-specific parsing APIs.

## Breaking changes

- Generated client parsing now validates through Standard Schema `validate()`
  semantics.
- `response.parse()` is now **async** and must be awaited.
- Generated client parse errors and generated server validation errors no longer
  expose `ZodError`; they now expose `StandardSchemaValidationError` with an
  `issues` array.
- Generated shared request/response typing for route, client, and server
  surfaces now relies on `StandardSchemaV1.InferOutput` instead of `z.infer`.
- Generated packages now include a shared `standard-schema.ts` helper and
  declare `@standard-schema/spec`.

## What did not change

- Generated files under `schemas/` are still emitted as Zod schemas.
- Existing Zod-based schemas generated by Craft continue to work because Zod v4
  implements the Standard Schema contract.

## Migration

1. Await manual parsing:

   ```ts
   const parsed = await response.parse();
   ```

2. Replace `ZodError` handling with `issues` handling:

   ```ts
   if (!result.isValid && result.kind === "parse-error") {
     console.error(result.error.issues);
   }
   ```

3. If you relied on generated `z.infer`-based request/response helper types,
   switch to the generated exported aliases or `StandardSchemaV1.InferOutput`.

4. Regenerate your output so the new `standard-schema.ts` helper and
   `@standard-schema/spec` dependency are included.
